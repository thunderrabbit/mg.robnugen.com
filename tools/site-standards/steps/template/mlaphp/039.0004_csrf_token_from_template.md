Chapter 4, ported. `csrf_token()` is the sibling of `csrf_field()`: a loose
function in `prepend.php` that reads `global $csrfProtect` and returns the
bare token, for `fetch()` callers that send it as the `X-CSRF-Token` header.
Rob chose its new home once, on base.robnugen.com, as the
`\Security\CSRFProtectaroo::getToken()` that already exists, reached through
the template's `$csrf`. With both helpers gone, every `Template` can require
the protector.

The check looks in every tracked PHP file outside `vendor/`, templates
included, for `csrf_token(`: its definition, a call, a commented-out call, or
`function_exists('csrf_token')`. `$_SESSION['csrf_token']` is a session key,
not the function, and is not counted. A site that never had `csrf_token()`
passes.

## How to do it

1. Do the `csrf_field()` step first, so every template has `$csrf`.
2. Change every `csrf_token()` in a template to `$csrf->getToken()`, keeping
   the `json_encode()` around it wherever it is written into JavaScript. Page
   code that called `csrf_token()` uses `$csrfProtect->getToken()`. Where a
   page only called it to set a template variable, drop the `set()` and have
   the template read `$csrf->getToken()`. A `function_exists('csrf_token')`
   guard goes, and what it guarded stays: left in, it is always false and the
   guarded script silently disappears. Commit (`Send CSRF tokens from the
   template's $csrf`).
3. Delete `function csrf_token()` from `prepend.php`. In the `Template`
   constructor, make the protector required:

       private readonly \Security\CSRFProtectaroo $csrf,

   and drop `|null` from its `@param`. PHPStan now names any `new Template`
   that step 3 of the `csrf_field()` step missed. A test that builds a
   `Template` passes `new \Security\CSRFProtectaroo(new \Mlaphp\Request())`.
   Commit (`Drop the global csrf_token()`).
4. Change the mentions of the two helpers that are left: `CSRFProtectaroo`'s
   class docblock, CLAUDE.md, and any comment in `phpcs.xml` that names
   `prepend.php`'s functions. Commit (`Document the template's $csrf`).
5. Run the site's gates, then this step's check, then `git grep -n
   'csrf_token(' -- templates`.

Do not touch a template that reads `$_SESSION['csrf_token']` directly. That
is a different habit, and what replaces it is Rob's to choose.

Live check once Rob has deployed to the test domain: use a page that posts
with `fetch()` (the template's is `/admin/migrate_tables.php`).

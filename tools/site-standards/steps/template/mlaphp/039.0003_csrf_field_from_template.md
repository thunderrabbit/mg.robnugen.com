Chapter 4, ported. The new-DH-user-site template has a loose `csrf_field()`
in `prepend.php` that reads `global $csrfProtect` and returns the hidden
input for a POST form. Rob chose its new home once, on base.robnugen.com: no
new class, because `\Security\CSRFProtectaroo::field()` already exists. Every
`Template` is handed the protector and shows it to its template as `$csrf`,
so a form writes `<?= $csrf->field() ?>`. On every other site an agent makes
the same move without him. `csrf_token()` is the next step.

The check looks in every tracked PHP file outside `vendor/`, templates
included, for `csrf_field(`: its definition, a call, a commented-out call, or
`function_exists('csrf_field')`. A docblock line may still say where the
function came from, and a variable named `$csrf_field` is not the function.
Where the `Template` class takes the protector, no page may set a template
variable named `csrf`. A site that never had `csrf_field()` passes.

## How to do it

1. In the site's `Template` class (`classes/View/Template.php`, or
   `classes/Template.php` on an older site), add the protector as the last
   constructor parameter, optional for now, and show it to the template after
   `extract()`. Commit it on its own (`Let a Template hand the CSRF protector
   to its page`).

       /**
        * @param \Security\CSRFProtectaroo|null $csrf Reaches the template as $csrf: a form
        *        writes <?= $csrf->field() ?>, a fetch() caller json_encode($csrf->getToken()).
        */
       public function __construct(
           \Config\Config $config,
           private readonly ?\Security\CSRFProtectaroo $csrf = null,
       ) {

   and, in the method that includes the template file,

       extract($this->vars);           // Extract the vars to local namespace
       $csrf = $this->csrf;            // After extract(), so a set('csrf') cannot replace it

   Keep whatever other parameters and body the site's constructor has.
2. **Look for a page variable already named `csrf`**: `git grep -nE
   "set\(\s*['\"]csrf['\"]"`. From step 1 on, the template's own `$csrf`
   replaces it without a word. Rename that variable in its page and its
   template first, in its own commit.
3. Pass `csrf: $csrfProtect` to every `new \View\Template(...)` a page script
   builds, layouts included, and add `@var \Security\CSRFProtectaroo
   $csrfProtect` to the page's "Set up by prepend.php" block. A class that
   builds a `Template` takes the protector as a parameter from the page that
   calls it. A script that does not include `prepend.php` and makes its own
   protector (the template's `wwwroot/login/register.php`) passes that one.
   Commit (`Pass the CSRF protector to every page's Templates`).
4. Change every `csrf_field()` in a template to `$csrf->field()`. A partial a
   template pulls in with `include` sees the same `$csrf`. Page code that
   called `csrf_field()` uses `$csrfProtect->field()`. A
   `function_exists('csrf_field')` guard goes, and what it guarded stays.
   Leave any variable named `$csrf_field` alone. Commit (`Render CSRF fields
   from the template's $csrf`).
5. Delete `function csrf_field()` from `prepend.php`, and change the mentions
   of it in `CSRFProtectaroo`'s docblocks and in CLAUDE.md. Commit (`Drop the
   global csrf_field()`).
6. Run the site's gates, then this step's check. Templates are outside what
   PHPStan reads, so also `git grep -n 'csrf_field(' -- templates`: one that
   was missed is a fatal error on that page.

Live check once Rob has deployed to the test domain: submit a form. A missing
token is a 403, so a broken form shows at once.
